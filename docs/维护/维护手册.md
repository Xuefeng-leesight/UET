# MRT Project Manager 维护、验证与发布手册

> 本文是维护目录唯一的权威文档，合并原维护准则、稳定交付标准、发布检查表和文档索引。架构、目录、依赖、多模态和 UI 规范见 [系统架构与 UI 规范](../架构/系统架构.md)。

## 1. 维护原则

1. 先证明现有行为，再改变结构。
2. 先确认 owner、调用链、契约、磁盘格式和失败回退，再编辑代码。
3. 优先复用现有接口；不因局部需求创建第二套注册表、Select、视频控件或状态模型。
4. 读取端先兼容旧格式，再写新格式；未知扩展字段应保留。
5. 自动化、模拟模式和截图不能替代真实设备与 Windows 验收。
6. 不覆盖工作区中与当前任务无关的用户改动。

## 2. 修改前检查

- 确认运行时：Renderer、main/preload、Python、脚本或独立工具。
- 用 `rg` 查找调用点、类型、测试、IPC/WS channel、路径和打包引用。
- 写下必须保持的字段、默认值、调用顺序、超时、清理和兼容行为。
- 检查 `git status`；现有修改默认属于用户。
- 先运行最窄静态检查；高风险改动必须准备并执行人工回归清单。
- UI 修改先对照相邻页面和 [UI 规范](../架构/系统架构.md#6-当前-ui-设计规范)。

## 3. 新代码放置

| 需求 | 位置 |
|---|---|
| React 领域页面、交互、状态 | `src/features/<domain>` |
| Shell、导航、跨领域协调 | `src/app` |
| 模态名称、页面与固定顺序 | `src/modalities` |
| Renderer IPC/浏览器适配 | `src/infrastructure` |
| Renderer 无领域 UI | `src/shared` |
| IPC handler/主进程领域 | `electron/domains/<domain>` |
| OS、Python、SDK、媒体 | `electron/platform` |
| 跨进程 DTO/纯算法 | 根级 `shared` |
| Python 协议 | `services/<service>/transport` |
| Python 用例/设备流程 | `services/<service>/application` |
| 厂商原始资源 | `SDK` |
| 迁移、安装、恢复 | `scripts` |
| 独立开发工具 | `tools/<tool>` |

新目录至少有一个清晰边界或两个稳定职责，不创建空的 `common/utils/components/hooks` 层。

## 4. 按变更类型维护

### 4.1 React 与 UI

- 页面只组合数据和组件，不解析 IPC channel、磁盘 JSON 或设备协议。
- 统计、归一化、时间换算、模态过滤提取为纯函数并测试。
- effect 必须清理 listener、timer、媒体、WebSocket 和陈旧异步结果。
- 修改公共视觉时同时检查中文/英文、空数据、长文本、禁用、loading、错误和窄窗口。
- 条件表单使用自动流式网格，不使用空 `<div />` 占位。
- 模态 UI 名称只从 `MODALITY_REGISTRY` 获取；“眼动模块/表情模块”不在多个页面重复硬编码。
- Sidebar 分组顺序来自固定注册顺序；工程模态数组顺序不得改变导航位置。
- 数据模态 Select 来源是工程能力，不来源于当前是否有记录。
- 等待状态文字为黑/深灰，黄色仅作小圆点；不要在列表重复显示模态彩色标签。
- 眼动和表情详情的返回、视频控制、视频路径与导出按钮保持一致。

UI 样式修改流程：

1. 先读架构文档第 6 节，按普通操作、透明文字、Tab、行内编辑、导航、开关、数据图形分类，再选择共享语义类；`btnGhost` 不等于透明文字样式。
2. 优先改共享变量或复用 `Modal`、`CustomSelect`、按钮/表格类；避免在页面写另一份主题色、遮罩和弹窗外壳、添加局部 `!important` 或通过 `role="switch"` / `data-visual-control` 规避普通按钮规则。
3. 用 `rg` 检索受影响的调用点和样式，包含设置子页、授权页、嵌套弹窗、Portal、数据加载后出现的操作。修改共享 CSS 时列出这些入口，不能只检查当前截图。
4. 在浏览器实际渲染后检查 computed style：背景、文字、边框、内外圆角与内边距关系、分层阴影及控件尺寸；仅搜索 JSX 的 `bg-*` 或看到 `bg-transparent` 不能证明灰底已消除。分别检查 hover、选中、展开和 disabled，动画既检查开始/进行过程，也等待结束再比较静态截图；单独检查减少动态效果模式。
5. 纯文档更新检查链接、参数与实现一致性；实际 UI 修改运行适用的类型/主题检查和针对性交互验证。不要以新增重复实现断言的测试替代渲染检查；模拟数据和平台标记检查须明确标注，不宣称已完成 Windows 实机验收。

UI 回归矩阵：浅色/深色 × Windows/macOS；同时检查中英文、短/长名称、常规/窄窗口、空态/有数据、loading/错误，以及默认/悬停/按下/选中/展开/禁用/键盘焦点。涉及数字时检查持续更新与位数增长；涉及动画时检查首次显示、关闭重开、内容更新和 `prefers-reduced-motion`。检查范围按本次影响面确定，修改公共主题或控件时覆盖其全部使用场景。

UI 回归清单（详细视觉参数以架构文档第 6 节为准）：

- [ ] 仅眼动、仅表情、多模态工程均无空白半行。
- [ ] Sidebar 公共入口、折叠分组、当前项、固定顺序正确；主导航与设置左侧默认透明，选中只有灰底，均无可见外边框，切换不跳尺寸。
- [ ] Select 有默认内容，菜单纵向，键盘/遮罩/禁用行为正常；向下/向上展开与触发框同色、零间距、接合处直角且无阴影缝；滚动和窗口变化后仍贴合。
- [ ] 普通输入、按钮、选择框在同主题同状态下灰阶一致，创建/保存等主要操作也为灰色；禁用不叠加透明度。文字名称、各级 Tab 和容器无灰底，工程名称仅悬停变色。
- [ ] Windows 中文字体、字重、控件圆角正确；正文与说明清晰；数字片段使用共享等宽字体与 `tabular-nums`，标签仍为正文比例字体。实际测量 `11` 与 `88` 的宽度，并检查 `9.9` → `10.0`，计时、百分比、单位及相邻操作不跳动，不通过改精度或截断数值掩盖宽度问题。
- [ ] 紧邻等距嵌套轮廓符合“外层 = 内层 + 内边距”：Select 与工程模态多选外层 12px / Windows 6px、内边距 4px、选项 8px / 2px。共享 Modal 使用独立外壳圆角 16px / Windows 12px，不从表单输入框加正文留白推算；下拉接合角仍为直角，圆形控件和数据图形未受影响。
- [ ] 弹窗标题、内容和操作区使用同一主表面，无灰色头尾条；默认左右 20px、标题上下 16px、正文上 4px / 下 20px、操作区上 0 / 下 16px。关闭文字/图标默认透明且点击区足够，长标题不挤压关闭按钮，短确认窗不保留大面积空白；遮罩为黑色 40% 且无背景模糊。
- [ ] 逐类盘点短确认窗、长表单、设置子页、嵌套添加窗、导出参数与预览；均复用共享 Modal，外壳不超过 `100dvh - 32px`，标题/操作区固定，正文按需滚动。检查小窗口及英文长标题、长动作文案，关闭和操作按钮始终可见，表格横向滚动不撑大外壳。嵌套关闭、遮罩/Escape、取消/确认遵循原契约，父级编辑状态、媒体和异步结果不因视觉修改被重置。
- [ ] 可多行标题采用平衡换行，中英文与窄窗口下没有明显末行孤词，连续长名称不溢出，不依赖硬编码换行；导航、状态栏及紧凑工具栏仍遵循单行布局。
- [ ] 分组入场只在显示或重开时执行；Modal 标题/内容/操作区为 160ms、错开 0 / 25 / 50ms，标题/操作区轻移 2px，内容区仅淡入，数据刷新不重播。入场期间打开 Portal 下拉仍零间距贴合；减少动态效果模式下立即显示。动画期间布局、键盘焦点、滚动、关闭及操作可用性正常，无累计延迟或残留透明内容。
- [ ] 表面优先色阶分层，需要分离的卡片、下拉及弹窗复用相应共享多层柔和阴影，浅深色均不过重、不在嵌套分组重复叠加；没有生硬装饰描边、立体按钮投影、渐变高光或文字描边。AOI 默认细边框、键盘焦点仍可辨，选择框接合处无阴影缝。
- [ ] 工程三点菜单及触发按钮四角完整；导出参数每次重开时全部分组收起、已选字段保留，展开后仍可正常勾选；总操作与各分组的全选/全不选逐列对齐，紧凑行距下检查窄窗口、长标题、滚动和键盘焦点。
- [ ] 表格表头固定、空状态和操作禁用正确。
- [ ] AOI 两级 Tab 透明；属性卡片默认细边框可见，名称/颜色行内透明，颜色下拉展开仍贴合；指标弹窗“全部显示”左侧，“全选 / 清空”并排右侧。
- [ ] 动态 AOI 关键帧文字区、共享时间轴标题/重置/范围选择无灰底；选中反馈、折叠、跳转、删除和范围操作正常。
- [ ] 统计报表两种模式按钮间距均为 8px；1 条、少量和多条数据的注视柱均不超过 24px，柱高与数值含义不变。
- [ ] 录制标题栏为不透明的中性主题色；视频画布、控制按钮和背景一致；圆形播放按钮、开关、颜色样本、校准目标与数据图形没有被普通按钮规则改形或去色。
- [ ] 玻璃主题开关复用 `Switch` / `SwitchVisual`：工程管理与新建工程的模态下拉、录制/面部设置、AOI/可视化侧栏、多选及时间轴用途开关均检查静止、按住、拖动和松手恢复。透镜及阴影不被下拉边缘裁断；保留业务颜色、至少一个模态、授权/禁用及键盘契约。拒绝/延迟状态、pointercancel、失焦、交互中切换主题与卸载不残留动画或指针捕获；静止开关不持续重绘，减少动态效果时直接更新。
- [ ] 面部分析页的结果/设置 Tab、时间轴标题和微表情展开文字无灰底；进度条点击层在启用、悬停、禁用时均透明，保留细轨道与点击范围；时间轴网格随浅深色主题切换。
- [ ] 授权页机器码展开/复制无灰底，License 输入及激活/导入按钮保持普通灰色；展开前后和错误提示同时检查。
- [ ] 图标按钮有名称，透明按钮仍可操作，禁用不能触发；导航与操作按钮的键盘焦点可辨，不能把“去外边框”扩展为移除焦点、Tab 下划线或 AOI 轮廓。
- [ ] 不出现已删除的标签、提示或跨模态数据。

### 4.2 新增或修改 IPC

1. 在 `shared/contracts/ipc/channels.ts` 登记 channel。
2. 在 `src/infrastructure/electron/clients` 增加 typed 方法。
3. 在 `electron/domains/<domain>` 验证 `unknown` 输入并注册 handler。
4. 通过 main 注入平台依赖；不在 main 写业务。
5. 增加 allowlist 对齐、成功、失败和非法输入测试。

禁止开放任意 channel、Renderer 直调 `window.ipcRenderer`、静默改名或在 preload 加业务判断。

### 4.3 WebSocket、设备和录制

Pupil AOI/通信原133列回归：运行 `node tests/export/check_aoi_export.mjs`、`node tests/export/check_aoi_export_ipc.mjs`、`node tests/recording/check_communication_bridge.mjs`、`node tests/recording/check_communication_start.mjs`、`node tests/trigger/check_recording_communication.mjs` 与 Python `tests.eye_tracking.pupil_core.test_communication_recording`。覆盖重叠/动态 AOI、停用范围、断流、完整注视去重、预览与文件逐格一致、UDP 真实回环、串口官方 MockBinding、原始字节、启动取消、端口打开/关闭失败重试、发送排空、日志恢复和错误状态。串口 MockBinding 和平台 CSS 检查不能代替 Windows/Linux/macOS 外设实机验收。

引入 `serialport` 后，安装包构建应执行 Electron 原生依赖重编译（`electron-builder install-app-deps`）；逐目标操作系统验证依赖装入与真实串口枚举、打开、收发、拔线和关闭。保留原有校准界面/其他设备流程，不把本机发送成功当外设 ACK。历史记录无通信日志时不补造内容。

- 保留命令、端口、字段、启动/停止确认语义。
- operation id 必须贯穿完整生命周期；陈旧响应不能覆盖新状态。
- 正常与异常退出都按 owner 清理资源。
- 表情/眼动组合启动失败执行局部回滚，停止失败保留其他模态产物。
- SDK 行为变化必须验证对应真实型号。

### 4.4 磁盘与迁移

- 新字段可选并有默认值；旧 project schema v1 继续按眼动模块读取。
- 迁移脚本说明输入根目录、备份、幂等、失败恢复。
- 验证“旧项目加载 → 保存 → 重载 → 回放 → 分析 → 导出”。
- 不在结构重构中顺便改用户目录或文件名。

### 4.5 新增模态

必须完成架构文档第 7 节的全部接入项，并重点验证：

- 工程创建与工程管理都可选择，且至少保留一个模态。
- 公共页面不复制；分析页面进入独立折叠分组。
- 导航固定顺序不受选择顺序影响。
- 录制、统一记录、详情、导出、预览形成闭环。
- 专属分析只加载本模态数据。
- 无记录时下拉仍显示工程模态。
- 旧工程和已有磁盘目录不受破坏。

### 4.6 拆分大型文件

1. 列出状态、I/O、纯计算、UI 和生命周期边界。
2. 为关键分支补特征测试。
3. 先移动纯函数/类型，保持兼容 facade。
4. 再提取单一资源 owner；一次迁移一个生命周期。
5. 每一步跑最窄测试与 typecheck。
6. 临时 facade 必须记录删除条件。

## 5. 测试策略

| 变更 | 最低证据 |
|---|---|
| 纯函数/模型 | 正常、边界、错误输入单测 |
| React 状态/生命周期 | 转移、重复挂载、清理、陈旧响应 |
| 模态注册/过滤 | 单模态、多模态、反向顺序、旧记录 |
| IPC | allowlist、输入验证、成功/失败 |
| Python 协议 | 解析、缺省、非法消息 |
| 录制 | idle → starting → recording → stopping → finalized/failed |
| 数据迁移 | 旧格式 round-trip、未知字段、幂等 |
| 媒体导出 | 文件、时长/尺寸、取消、失败清理 |
| UI | 实际渲染、空态、条件布局、中文/英文 |

## 7. 人工回归矩阵

- 桌面式 Pro/A8、眼镜式设备；配置与实际 SDK 一致/不一致。
- 仅眼动、仅表情、多模态；音频开/关。
- 工程创建、关闭重开、工程模态修改、Sidebar、录制、记录合并、导出。
- 数据导出切换模态后，列表、参数、导出、预览同步变化。
- 单机/多机，本地/远程停止。
- 正常停止、设备断连、WS 断连、停止超时、应用退出、磁盘不足。
- 记录回放、Marker、时间轴、Visual、AOI、映射、报表和洞察。
- 眼镜式完整视频刺激物：Pupil、aSeeGlassesPlus、HH_ET28 及新接入型号共用整段视频条；无眼动或空刺激物列、切换记录、旧 AOI 重载、视频缺失及媒体时长迟到均检查。
- 主窗口、被试窗口、多显示器、全屏进入/退出和窗口恢复。

## 8. 稳定交付标准

发布阻断项全部通过才可发布：

1. `npm run release:check`、常规 CI 成功。
2. Windows workflow 生成两个 Python exe、NSIS 包和 SHA-256。
3. 干净 Windows 完成安装、首次启动、退出、重启、升级/卸载。
4. 支持设备矩阵完成连接、校准、录制、停止、断连和超时。
5. 旧项目 round-trip；三种模态工程完成页面、录制、记录、分析和导出验证。
6. 没有未处理 P0/P1 发布阻断缺陷；已知限制写入发布说明。
7. 记录版本、commit、SDK 来源/清单、测试证据和批准人。

自动化负责可重复证据；真实 SDK、USB、网络、多显示器、摄像头、长采集、Windows 体验和科学有效性必须人工验收。

ET28 红外预览另外运行 `tests.eye_tracking.huahong.test_eye_preview`、`test_recording_runtime`、`test_transport` 和 `node tests/recording/check_huahong_eye_preview.mjs`。检查厂商左右半幅映射、回调内存复制、预览最新帧边界、无效帧、断连迟到回调，以及眼图不进入录制缓冲、不刷新场景健康、不挤掉慢客户端场景帧。前端执行真实消息处理和眼图 effect，覆盖原开关、左右分槽、场景隔离与旧连接清理；Windows 实机必须逐眼遮挡核实左右标签及图像方向，并在校准、连续录像和拔线重连期间验收。

### Pupil 原生后端维护

默认 Pupil 环境为 `services/eye_tracking/adapters/pupil_native/.venv`，用该环境的 Python 运行 `scripts/install-pupil-native.py` 安装基础依赖及固定源码的 LGPL pye3d，构建再安装 `services/eye_tracking/requirements/pupil-build.txt`。不要将两种 OpenCV 包或旧厂商 DLL 混装到此环境。`MRT_PUPIL_BACKEND=capture` 仅用于显式对照，切换后须重新连接、校准。

运行 `python -m unittest discover -s tests/eye_tracking -t . -v`；测试需要本机 loopback。原生专项覆盖实际检测器接口、上游数值拟合、异步启动取消、迟到进程释放、溢出、断连、事件单位及无效数据边界。打包后设置 `MRT_PUPIL_EXECUTABLE` 为绝对路径，另运行 `test_native_boundaries.NativeBoundaryTests.test_packaged_native_fit_without_python_environment`（完整模块前缀 `tests.eye_tracking.pupil_core.`）及 `test_runtime.ProductionRuntimeTests.test_production_entrypoint_parent_pipe_shutdown`。前者检查冻结算法依赖，后者检查正式入口、共享追踪器及父进程退出。

修改原生管道清理时运行 `tests.eye_tracking.pupil_core.test_parent_pipe`，其中真实子进程在父控制输入关闭后继续写入末尾视频帧，验证父进程排空输出直到 EOF，并丢弃迟到样本。保留活跃期间的溢出/解码错误，不能通过吞掉全部管道异常消除正常停止时的 Windows `Errno 22`。

发行必须完整携带 `services/dist/pupil-backend/`（Windows/Linux 为可执行文件及 `_internal/`，macOS 为整个 `PupilBackend.app`），安装资源路径为 `py/pupil-backend/`；不要只复制入口文件。附带 `services/dist/pupil-third-party` 的许可证、来源、实际版本、可重建源码及自动生成的后端校验清单。构建后的首次冻结程序运行必须先执行 `tools.pupil.benchmark_startup`，以真实 `algorithm_ready` 为终点，4秒为性能预算；命令见[原生后端说明](../../services/eye_tracking/adapters/pupil_native/README.md)。180秒异常超时不能代替性能验收，重复运行不能标为冷启动。macOS 标准应用包支持 `MRT_PUPIL_CODESIGN_IDENTITY`；发行签名、公证和干净机器首次安装仍须验收。Windows 需另外验收 libUSBk 驱动、相机身份/内参、独立算法与打包依赖。执行现有 `npm run release:check`，并确认 `git diff -- src` 为空。字段语义与待真机项目见 [Pupil 原生方案](../方案/PupilCore原生后端方案.md)。
