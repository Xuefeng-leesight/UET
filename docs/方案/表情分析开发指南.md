# 表情分析开发指南

> 状态：Implementation Draft v0.4（记录域隔离修订）  
> 更新日期：2026-08-04  
> 目标产品：UET-SA 视线交互采集分析系统  
> 目标用途：正式研究报告辅助分析  
> 技术路线：Python 后端离线分析，Electron/React 前端负责配置、任务管理、展示与人工复核

## 1. 文档目标

本文用于指导“表情分析”模块的产品设计、数据采集、Python 分析服务、时间同步、结果展示、质量控制和正式报告输出。

模块分为三个分析大类：

1. **情绪**：连续效价/唤醒度、离散情绪概率、情绪区间与转换。
2. **表情**：面部动作、强度、对称性、持续时间和事件阶段。
3. **微表情**：短时面部动作候选、Onset/Apex/Offset 定位和人工复核。

本模块必须将“模型观察结果”与“受试者真实心理状态”区分开。未经验证的模型输出不得作为医学诊断、人格判断或确定性心理结论。

## 2. 核心设计原则

- 正式分析由 Python 后端执行；前端不承担最终模型推理。
- 原始人脸视频是最终分析依据，必须保留且不可被预览流替代。
- MediaPipe 只作为人脸关键点、Blendshape 和姿态基础特征提取器。
- 情绪与微表情结论必须来自版本化、经过验证的后续模型或算法。
- 所有结果必须可追溯到原视频、模型版本、参数、帧时间戳和人工审核记录。
- 所有数据必须与刺激物、AOI、眼动数据和实验 Marker 使用同一记录时间轴。
- 质量不足时必须降级或拒绝分析，不能强制输出结果。
- 正式报告必须展示置信度、有效数据比例、限制条件和算法版本。

MediaPipe Face Landmarker 支持视频模式、人脸关键点、Blendshape 和面部变换矩阵输出。官方接口要求视频帧时间戳单调递增：

- [Face Landmarker](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/FaceLandmarker)
- [FaceLandmarkerResult](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/FaceLandmarkerResult)
- [52 项 Blendshape](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/drawing_styles/face_landmarker/Blendshapes)

页面结构必须复用 AOI 分析页的工作区语言：左侧为单一圆角工作区，包含顶部工具栏、视频画布、进度条、居中播放控制器和可折叠时间轴；右侧为固定 `300px` 面板。时间轴默认收起，展开后同时显示情绪、微表情、表情三条轨道，不再使用三个互斥分页。三条轨道必须共享视频播放头和统一时间刻度。

没有人脸视频时，视频区域使用与 AOI 相同的浅灰空画布和居中提示；加载真实视频后切换为黑色画布并以 `object-contain` 显示。摄像头、导入、同步、模型和任务设置放在右侧“分析设置”中。

### 3.3 记录选择与命名规则

右侧最顶部必须提供记录选择器，数据来源只扫描当前工程的 `facial-analysis` 记录清单。

要求：

- 人脸分析与眼动是两个独立记录域；人脸视频、清单和分析结果只存放在 `facial-analysis`。
- 仅人脸录制不得创建眼动 CSV、眼动 meta、points index，也不得出现在 AOI、热图或眼动记录列表。
- 同步录制时两端使用相同显示名称和共同起始时间基准，但分别持久化；可保存关联 ID 用于对齐，不形成目录依赖。
- 人脸记录下拉框显示 `facial-video.json` 中持久化的 `recordName`。
- 不得直接显示未经处理的文件名，也不得自行拼接受试者名称。
- 默认优先选择与当前系统选择 ID 对应的人脸记录；不存在时选择第一条有效人脸记录。
- 切换记录时同步切换人脸视频、分析任务、同步信息和结果，不保留上一记录结果。
- 导入外部人脸视频绑定到人脸记录，不要求存在眼动记录。
- 同一记录可以重新绑定人脸视频，但必须保留变更审计和旧分析失效状态。

推荐前端契约：

```ts
interface FacialAnalysisPageProps {
  projectDir: string | null;
  selectedRecordId: string | null;
  setSelectedRecordId: (recordId: string | null) => void;
}
```

保存关系：

```text
一次实验录制（共享名称与时间基准）
├── recordings/：设备视频、眼动 CSV、眼动 meta
└── facial-analysis/<facial-record-id>/
    ├── source/face.mp4
    ├── facial-video.json
    └── result.json
```

所有 JSON 中的工程内文件路径必须保存为相对工程根目录的路径；读取时兼容旧版绝对路径，但新写入禁止绝对路径。

#### 情绪分析结果

显示要求：

- 标题显示当前时间点或当前选中时间区间的主导情绪。
- 横向条形图显示各情绪类别的概率或占比。
- 每个类别使用固定、可访问的颜色映射。
- 同时显示数值，不能只依赖颜色和长度。
- 概率总和应接近 100%；若展示时间区间占比，标题必须明确写“时间占比”。
- 低置信度时显示“不确定”，不得强制选择最高类别作为确定结果。
- 支持“当前帧”“当前事件”“当前刺激物”“选择区间”四种统计范围。
- 鼠标悬停显示样本数、有效时长、置信度和质量等级。

第一版建议情绪标签：

- 中性
- 愉悦
- 悲伤
- 愤怒
- 惊讶
- 恐惧
- 厌恶
- 不确定

“兴趣”和“放松”若要作为正式标签，必须由情绪模型明确支持并经过独立验证，不能只通过 Blendshape 规则生成。

#### 表情强度矩阵

显示要求：

- 行表示表情事件或面部动作。
- 列表示离散强度区间。
- 最后一列显示原始最大值或标准化最大强度。
- 当前强度所在列用色块突出。
- 点击一行后，左侧视频和时间轴跳转到对应峰值事件。
- 支持按“当前帧、当前事件、当前刺激物、选择区间”刷新。
- 强度区间必须来自版本化分析配置，而不是前端临时计算。

推荐强度等级：

```text
无 / 轻微 / 少量 / 明显 / 强烈
```

内部仍保存连续值；离散等级只用于展示和报告汇总。

第一版表情动作建议优先展示：

- 微笑
- 皱眉
- 眉毛抬起
- 眼睛睁大
- 眨眼
- 面颊抬起
- 鼻翼收缩
- 嘴角下压
- 嘴唇收紧
- 张嘴
- 左右不对称

“大笑、沮丧、尖叫”等复合语义不能仅靠单个 Blendshape 判断，必须由经过验证的组合规则或模型输出。

#### 面板联动

- 视频播放时，右侧结果按视频时间更新，但刷新频率建议限制在 5–10 Hz。
- 暂停时显示精确当前帧结果。
- 选择时间区间后切换为区间统计，不再随播放头自动变化。
- 切换刺激物或 AOI 后，右侧显示对应范围的结果摘要。
- 当前记录没有人脸视频时，显示导入/配置入口，不显示空的零值图表。
- 当前记录尚未分析时，显示“开始分析”，不能将所有类别显示为 `0.00` 冒充有效结果。

#### 结果状态

右侧面板必须明确区分：

```text
未配置人脸视频
等待分析
分析中
分析完成
存在质量警告
分析失败
结果已过期，需要重新分析
```

## 4. 右侧面板的设置模式

用户点击右侧“设置”后，显示以下设置分组；返回“分析结果”时保留未保存的设置草稿并提示保存状态。

### 4.1 人脸摄像头

字段：

- `启用人脸视频采集`
- `摄像头设备`
- `分辨率`
- `目标帧率`
- `视频编码`
- `镜像预览`
- `采集前质量检查`
- `刷新设备列表`
- `测试画面`

建议默认值：

```json
{
  "enabled": false,
  "width": 1280,
  "height": 720,
  "targetFps": 30,
  "codec": "h264",
  "mirrorPreview": true,
  "qualityCheck": true
}
```

约束：

- 情绪与普通表情分析最低建议 720p/30 FPS。
- 微表情正式分析建议使用支持高帧率的独立摄像头。
- 低帧率视频只能输出“快速表情候选”，不能输出确定的微表情结论。
- 摄像头设置必须保存稳定设备标识，不应只保存系统显示名称。
- 摄像头不可用时，开始实验前必须明确提示，但是否阻止实验由工程设置决定。

### 4.2 实验录制时同步采集

字段：

- `实验录制时同步采集人脸视频`
- `摄像头失败时阻止实验录制`
- `录制前倒计时`
- `保存原始音频`（默认关闭）
- `录制状态显示`

推荐正式研究默认策略：

- 同步采集：开启。
- 摄像头失败时阻止实验：开启。
- 保存原始视频：必须开启。
- 预览失败但后端录制正常时：允许继续。
- 后端录制失败时：阻止正式实验开始。

同步采集的启动顺序：

1. 检查摄像头与磁盘空间。
2. 创建统一的 `recordingSessionId`。
3. 记录单调时钟起点和系统时间。
4. 启动人脸视频采集并等待后端确认。
5. 启动眼动/设备录制。
6. 启动刺激物播放。
7. 将各链路首帧时间和偏移写入同步清单。

停止顺序：

1. 停止刺激物播放和 Marker 产生。
2. 停止眼动/设备录制。
3. 停止人脸视频采集。
4. 等待视频封装完成。
5. 保存统一同步清单。
6. 创建可供分析的任务记录。

### 4.3 导入外部人脸视频

字段：

- `允许导入外部人脸视频`
- `选择视频`
- `绑定记录`
- `同步方式`
- `时间偏移`
- `导入后复制到工程`
- `验证视频`

支持的同步方式：

1. **统一时间戳**：外部视频包含可信的绝对时间。
2. **Marker 对齐**：视频中存在同步灯、声音或外部事件 Marker。
3. **手动时间偏移**：用户在视频与刺激时间轴上选择同一事件。
4. **共同开始点**：仅在采集设备确认同时启动时使用。

外部视频不得只保存原路径引用。正式研究模式下应复制到工程目录，并计算 SHA-256 校验值。

### 4.4 自动时间对齐

字段：

- `自动与刺激物对齐`
- `自动与 AOI 对齐`
- `自动与眼动数据对齐`
- `同步偏移修正（ms）`
- `同步质量`
- `打开同步校验工具`

默认全部开启。

必须使用记录的统一局部时间轴：

```text
t_record_ms = t_source_monotonic - recording_start_monotonic + source_offset_ms
```

关联规则：

- 刺激物：按刺激物开始/结束 Marker 划分区间。
- AOI：使用现有 AOI 时间段与命中事件。
- 眼动：按记录局部毫秒时间匹配最近采样或时间窗口。
- 人脸帧：保留真实帧 PTS，不按名义帧率推算。
- 可变帧率视频：必须通过 FFmpeg/容器时间戳解码。

自动对齐结果必须包含：

- 估计偏移
- 对齐方法
- 对齐置信度
- 最大误差估计
- 是否经过人工确认

### 4.5 分析设置

字段：

- 分析大类：情绪、表情、微表情
- 人脸检测置信度阈值
- 人脸存在置信度阈值
- 跟踪置信度阈值
- 个体基线区间
- 时间平滑强度
- 头部姿态过滤阈值
- 最低质量阈值
- 情绪模型版本
- 微表情检测配置版本

正式报告模式下不允许直接编辑底层阈值；应选择经过验证并锁定的“分析配置版本”。高级调试模式才允许修改单项参数。

### 4.6 分析任务

显示：

- 当前任务状态
- 分析阶段
- 已处理帧数/总帧数
- 有效帧比例
- 预计剩余时间
- Python 服务状态
- 开始分析
- 取消分析
- 重新分析
- 打开结果目录
- 导出正式报告

## 5. Python 后端架构

### 5.1 接入方式

复用现有 `services/eye_tracking/entrypoints/server.py` 命令 WebSocket，不在前端创建第二套分析服务。

新增独立模块，避免继续扩大主服务文件：

```text
services/facial_analysis/application/
```

```text

  → validating
  → decoding
  → face_landmarks
  → quality_assessment
  → baseline
  → expression_analysis
```

## 6. 人脸视频采集

### 6.1 摄像头枚举

建议由 Python/OpenCV 或平台采集层枚举摄像头，返回：

```json
{
  "device_id": "stable-device-id",
  "name": "USB Camera",
  "backend": "dshow",
  "supported_modes": [
    { "width": 1280, "height": 720, "fps": 30 },
    { "width": 1280, "height": 720, "fps": 60 }
  ]
}
```

Windows 打包版本应优先验证 DirectShow/Media Foundation 的稳定设备标识。设备序号不能作为长期配置，因为插拔后可能变化。

### 6.2 录制文件

建议目录：

```text
recordings/<record-id>/
├── device_video.*
├── eye_data.csv
├── face_video.mp4
├── face_video.metadata.json
└── synchronization.json
```

`face_video.metadata.json` 至少包含：

- 摄像头稳定 ID 和名称
- 请求/实际分辨率
- 请求/实际帧率
- 编码器和像素格式
- 开始/结束系统时间
- 开始/结束单调时间
- 首帧/末帧 PTS
- 编码丢帧数
- 文件 SHA-256

## 7. 分析流水线

```text
输入验证
  → FFmpeg 获取真实帧时间戳
  → 视频逐帧解码
  → MediaPipe Face Landmarker
  → 人脸质量评估
  → 个体基线归一化
  → 表情动作事件
  → 情绪模型
  → 微表情候选
  → 刺激物/AOI/眼动对齐
  → 结果保存
  → 正式报告
```

### 7.1 MediaPipe 特征

每个有效帧保存：

- 时间戳
- 人脸检测/存在/跟踪置信度
- 归一化关键点
- 52 项 Blendshape
- 面部变换矩阵
- 头部 yaw/pitch/roll
- 人脸边界框
- 质量指标

逐帧特征建议使用压缩二进制、Parquet 或分块 JSONL。长视频不应保存为单个巨大 JSON 数组。

### 7.2 情绪

第一版输出：

- 效价
- 唤醒度
- 中性及离散情绪概率
- 主导情绪
- 不确定状态
- 情绪事件区间

MediaPipe 不直接输出情绪。情绪模型必须具有独立版本、训练数据说明、验证指标和适用人群限制。

### 7.3 表情

输出：

- 原始 Blendshape
- 面部区域动作
- 动作强度
- 左右对称性
- Onset/Apex/Offset
- 持续时间
- 事件峰值帧

若映射 FACS，应写为“基于 Blendshape 的动作估计”，除非已经完成与专业 FACS 编码者的一致性验证。

### 7.4 微表情

输出必须使用“微表情候选”术语，包含：

- Onset
- Apex
- Offset
- 持续时间
- 主要动作区域
- 动作强度
- 质量分
- 候选置信度
- 人工审核状态

帧率或质量不足时自动降级为“快速表情候选”或禁用该分析。

## 8. 质量控制

每条记录必须生成质量报告：

- 人脸检测覆盖率
- 有效分析帧比例
- 实际帧率和帧间隔波动
- 人脸区域像素尺寸
- 光照、模糊、遮挡
- 头部姿态范围
- 多人出现比例
- 丢帧和时间戳异常
- 基线区间有效性
- 同步质量

建议质量等级：

- A：可用于全部已验证分析。
- B：可用于情绪趋势和表情，微表情需谨慎。
- C：仅可用于表情动作参考。
- D：拒绝生成正式结论。

正式报告不得隐藏质量等级和无效数据比例。

## 9. 时间同步与联合分析

### 9.1 统一时间轴

所有数据转换为记录局部时间 `recordTimeMs`：

```ts
interface AlignedFacialFrame {
  recordTimeMs: number;
  sourceTimeMs: number;
  stimulusId?: string;
  stimulusLocalTimeMs?: number;
  aoiHits?: string[];
  nearestGazeSampleTimeMs?: number;
  markerIds?: string[];
}
```

### 9.2 刺激物

- 桌面式记录按现有刺激物局部时间轴对齐。
- 眼镜式记录默认按记录全局时间轴对齐；如存在刺激播放 Marker，再建立刺激区间。
- 刺激物切换边界附近必须保留误差窗口，避免错误归属。

### 9.3 AOI

- 使用已保存 AOI 定义和时间区间。
- 对动态 AOI 使用对应视频局部时间。
- 输出“表情事件发生时命中的 AOI”和“AOI 注视后指定窗口内的表情变化”。

### 9.4 眼动数据

- 不强制一帧对应一个眼动采样点。
- 支持最近采样、线性插值和时间窗口统计。
- 联合指标必须记录所采用的匹配策略和容差。

## 11. 正式研究报告

报告至少包含：

1. 工程、实验、记录和受试者标识。
2. 人脸摄像头与视频规格。
3. 有效分析时间和有效帧比例。
4. 同步方法、偏移和同步质量。
5. MediaPipe、模型和分析配置版本。
6. 情绪趋势与概率，不确定区间。
7. 表情动作统计和事件。
8. 微表情候选及人工审核状态。
9. 与刺激物、AOI、眼动数据的联合指标。
10. 局限性、排除区间和质量警告。

禁止在报告中：

- 将情绪概率写成确定事实。
- 将微表情候选直接写成欺骗、意图或人格结论。
- 隐藏低质量、无脸和遮挡区间。
- 混用不同模型版本而不说明。
- 在没有人工复核时把微表情候选写成确认事件。

报告应支持 PDF、HTML、CSV/JSON 数据附件，并保留可机器读取的分析清单。

## 12. 隐私、伦理与权限

人脸视频属于高敏感个人数据。正式研究模式必须提供：

- 知情同意确认
- 采集用途说明
- 保存期限
- 数据删除机制
- 导出权限控制
- 原视频和分析结果分级访问
- 操作审计日志
- 可选的视频加密存储
- 报告匿名化

删除受试者或记录时，应明确询问是否一并删除人脸原视频、分析特征、截图和报告。

### 13.2 实验录制监控模块组合规则

实验录制页的监控区域包含两个具有录制语义的模块：

- `设备录制画面`：眼动设备及眼动数据录制模块。
- `人脸检测`：人脸摄像头及表情视频录制模块。

模块是否被用户从监控区域“移除”决定是否参与下一次录制；单画面、2×2、3×3 只控制显示布局，不改变录制配置。

启动矩阵：

| 设备录制画面 | 人脸检测 | 开始录制行为 |
|---|---|---|
| 启用 | 启用 | 眼动与人脸同步录制 |
| 启用 | 移除 | 仅执行原有眼动录制流程 |
| 移除 | 启用 | 不启动眼动设备和校准，仅录制人脸视频 |
| 移除 | 移除 | 禁止开始并提示至少恢复一个模块 |

约束：

- 仅眼动分支不得调用人脸采集接口。
- 仅人脸分支不得调用眼动设备、校准或眼动 WebSocket 录制命令。
- 组合分支先按原流程启动眼动，再以旁路方式启动人脸；人脸启动失败必须提示，但不得损坏已经开始的眼动记录。
- 仅人脸录制完成后仍创建一条与现有记录列表兼容的实验记录，并通过该记录 ID 关联人脸视频。
- 人脸摄像头必须在“人脸检测”监控块内检测和选择。
- 为保持既有眼动录制行为，首次进入和“恢复默认”均只启用眼动模块；用户通过顶部“+ 人脸检测”明确加入后才进入组合录制配置。

## 16. 验收标准

### 16.1 采集

- 能稳定选择并重新识别人脸摄像头。
- 人脸视频与实验录制同时启动、停止。
- 录制失败时按配置阻止实验。
- 应用异常退出后能够识别和修复未完成视频。
- 元数据包含真实帧率、时间戳和哈希。

### 16.2 记录选择与结果面板

- 记录列表与眼动记录列表使用同一组 `RecordingRecord`。
- 所有选项显示值与 `getDisplayRecordName(record)` 完全一致。
- 表情结果、外部视频和同步配置都通过 `record.id` 关联。
- 切换记录后不会短暂显示上一记录的分析结果。
- 未分析、分析失败和低质量状态不会显示为全零有效数据。
- 情绪条形图数值、颜色和统计范围表达明确。
- 表情强度矩阵可以跳转到对应事件峰值。

### 16.3 分析

- 相同视频、模型和配置重复分析结果一致。
- 长视频分析不阻塞眼动 WebSocket 和前端操作。
- 任务可取消、失败可重试、结果可恢复。
- 无脸、多人、遮挡和低帧率能够正确降级。
- 逐帧结果可追溯至原视频时间戳。

### 16.4 同步

- 人脸、眼动、刺激物和 AOI 使用统一记录时间轴。
- 用户可以查看并修正同步偏移。
- 报告展示同步方式和同步质量。
- 自动测试覆盖固定帧率、可变帧率和外部导入视频。

### 16.5 报告

- 报告包含数据质量、版本和限制条件。
- 所有统计结果可追溯到记录和原始事件。
- 微表情候选区分待审核、确认和驳回。
- 导出的机器可读数据与页面统计一致。

## 17. 第一阶段暂不实现

- 根据面部表现推断欺骗或真实意图。
- 医疗或心理疾病诊断。
- 未经验证的跨文化统一情绪结论。
- 仅凭眼图进行完整表情分析。
- 仅凭 30 FPS 视频输出确定微表情结论。
- 云端上传和云端人脸识别。
- 多人同时分析。

## 18. 待确认事项

在阶段 0 结束前确认：

1. 正式采购/支持的人脸摄像头型号与最高帧率。
2. Windows 是否为首个正式发布平台。
3. 人脸视频默认保存期限和删除规则。
4. 情绪模型的目标人群、语言和文化范围。
5. 正式情绪标签集合。
6. 微表情验证数据集和人工编码规范。
7. 是否要求双人独立复核及一致性统计。
8. 报告机构名称、模板、审批和签名要求。
9. 是否对原始视频和分析结果启用磁盘加密。
10. 研究伦理审批和知情同意模板。

## 19. 当前建议的后续开发任务

P0–P3 首轮实现完成后，下一可交付任务应集中于验证和加固：

1. 安装并冻结 OpenCV、MediaPipe 和 PyInstaller 依赖版本。
2. 在目标 Windows 机器验证摄像头枚举、30/60 FPS 采集和打包运行时。
3. 增加实时测试画面、分析任务进度和取消机制。
4. 使用真实人脸视频验证事件阈值、质量门控和长视频内存。
5. 增加同步校验工具和 Marker 偏移估计。
6. 完成人工复核、CSV/JSON 导出和正式报告前置数据。

情绪模型仍不得在缺少验证集、模型版本和适用人群说明时启用。微表情事件继续保持“候选”语义，不能直接写成确定结论。
