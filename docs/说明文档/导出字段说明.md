# 导出字段清单与定义


## 一、眼动模块 CSV 字段

**通用约定**

- 行类型取决于源文件：7invensun 可在采样行上携带事件状态；Pupil/华弘还包含独立事件行。Pupil 事件行由 `source_event_type` 区分，不能当作新增 gaze 或瞳孔采样。
- 眼动导出以原有 **133 列及其顺序、表头为唯一标准**，不提供来源/质量/归一化扩展列。原有受试者自定义属性功能保留，默认不选，不计入 133 列。
- 源 CSV 中找不到对应列时，该单元格输出**空串**（不会报错，也不会写 0）。
- 字段按选择顺序写出，表头顺序即勾选面板中的顺序。

### Pupil 三维平滑的算法与使用边界

这是本软件新增的导出派生算法，版本为 1；Pupil Core 原始输出本身没有这组独立平滑结果。推荐、左眼、右眼分别维护三维状态，使用固定时间常数 `τ = 25 ms`，按实际时间间隔计算 `α = 1 − exp(−Δt/τ)`，然后逐轴计算 `s(t) = s(t−1) + α × (raw(t) − s(t−1))`。首个合格点仅初始化状态，第二个连续合格点起输出。算法版本和参数在内部派生上下文中保存，用户导出仍为原 133 列。

推荐流使用明确的 gaze 源时间；单眼优先使用该眼原始测量时间。只有历史文件整列缺失时才按明确的替代时间规则处理，不能拿空单元格猜时间。重复底层眼测量不作为新增样本。缺失或不合格三维量、非递增时间、迟到数据、超过 100 ms 的间隔、可识别的连接/映射/尺寸变化会重置相应状态；独立事件和纯标记不作为 gaze 输入。单眼无效不清除另一只独立有效眼。新录制内部保留真实场景宽高和尺寸变化代次，防止相机先改变尺寸又恢复时跨段平滑；历史未保存的变化无法事后识别。

该滤波会抑制高频变化并引入响应滞后，`25 ms` 是软件参数，不是精度承诺，也不是对 7invensun 未公开平滑算法的复现。三维点依然处于随头部运动的世界相机坐标系，不是固定实验室空间坐标；不会由此改善原始深度模型或完成跨设备配准。既有注视、眼跳和速度分析继续使用其原始数据与算法，不改用这组导出平滑值。

已知眨眼/坏质量采样会断开对应状态；独立眨眼事件行被忽略，不据此承诺完整眨眼区间均被屏蔽。历史未保存的接收顺序或尺寸变化不能事后重建，计算以现有证据为限。

Pupil Core 使用现有“设置 → Trigger”配置。UDP 开关启用指定接收端口及发送地址；串口开关独立配置端口、波特率、数据位、停止位和校验位。开始录制时，软件完成时钟对齐和端口打开后才允许播放刺激物；停止时先关闭接收、等待已提交发送完成，再关闭录制文件。串口未开启时不打开设备。现有刺激物 Trigger 标记通过已启用通道发送 UTF-8 十进制文本，不附加换行。

四列只在实际收发事件行有值，一行一个方向。UDP 发送以操作系统成功回调为依据，串口发送以 `write + drain` 完成为依据；二者均不代表外设收到或执行。UDP 接收按数据报保存；串口按实际读取字节块保存，不把块边界当作外设协议包边界。通信行不参与眼动采样率、有效率、速度和注视计数。

内容统一采用可逆的单行 JSON：有效 UTF-8 为 `{"encoding":"utf-8","data":"..."}`，任意二进制为 `{"encoding":"base64","data":"..."}`。空包也有 envelope；换行、制表符和零字节保留为 JSON 转义，避免破坏 CSV 物理行边界。读取后先解析 CSV，再解析 JSON；`base64` 的 `data` 解码还原原字节。不得用字符串去空格、换行删除或损坏字节替换来“清洗”通信原文。

事件视频时间来自实际 I/O 观察时刻的单调时钟，与 Pupil 本次录制源时钟通过三次往返中的最低延迟样本对齐。估计不确定度记录于内部诊断；这是软件时钟对齐，不是硬件触发同步精度保证。每条收发先在本次录制 `.pupil/communication-capture.jsonl` 持久化，再向后端提交；后端日志与捕获日志按事件 ID 去重，断连恢复仍读取捕获日志。端口或落盘错误会明确提示并标记录制为部分完成，不能把异常记录显示成全部成功。历史录制从未保存的通信无法事后补造。
