## 校准得分现在有了，融合误差还未解决

校准附档含 90 条参考和 726 条瞳孔消息，88 对匹配观察，分三个目标采样段。保存的训练统计与离线重算逐项吻合，工程 monitor 文件中的左右眼得分也一致：

| 模型 | 本次平均训练误差 | 本次 P95 | 上次修复后模型重放均值 |
| --- | ---: | ---: | ---: |
| 左眼 | 7.87 px | 14.35 px | 8.08 px |
| 右眼 | 11.39 px | 36.82 px | 7.90 px |
| 双眼融合 | 23.72 px | 63.10 px | 20.30 px |

得分是训练重投影误差，单位为 1280 × 720 场景图像像素，越小越好。这里验证了得分计算与保存，没有实际操作 Windows 前端确认显示。

水平向右、垂直向下为正。第一个目标的融合点明显偏左，而且误差大于两个单眼各自的误差。整体左移平均值约 15.32 px，但其他目标偏差方向不同，不应直接给全部 gaze 加固定偏移。

目前校准代码使用总体平均归一化训练误差作为粗略拒绝条件，没有逐目标融合误差的验收门槛，因此“校准成功”和“左右眼得分较小”无法排除这类局部融合偏差。后续应优先检查第一目标采样质量、双眼融合几何及逐目标质量判定，而不是只补前端字段或用单眼平均替换融合点。

现有数据不能区分参照位置/视线变化、眼模型几何、默认内参和深度假设分别贡献多少误差。相机仍使用型号默认内参；眼/场景延迟仍为 15/70 ms 软件估计。**`independentValidationPerformed=false`，没有独立目标验证真值，实际注视准确性仍未验收。** 本次也未重新拟合或修改保存模型。
