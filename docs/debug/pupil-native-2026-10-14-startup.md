# 2秒算法就绪目标与本轮测量

状态：优化、分段诊断及自动门禁已落地；首次启动尚未稳定达到2秒，不能以重复启动或单次最好成绩替代验收。

## 实施

- PyInstaller使用独立PKG代码归档，启动程序从约11MB减到约87KB。macOS归档作为受包签名覆盖的Resources文件，由MacOS目录链接；Windows与exe同目录，由COLLECT收集。原有整个pupil-backend目录交付方式不变，不能遗漏pkg文件。
- 排除仅构建时需要的setuptools，避免其运行时钩子在所有服务/相机/拟合子进程入口之前导入构建工具。保留完整NumPy、OpenCV、SciPy、UVC、pupil-detectors和pye3d准备检查，不提前报告就绪。
- 构建脚本拒绝缺失或空的PKG，完整校验清单包含归档；macOS深度严格签名验证通过。未禁用系统校验、未移除算法依赖。
- 版本 `pupil-native-v5-startup`。在入口及运行时导入完成后记录perf_counter分段，基准报告增加进程至Python入口、运行时导入、端口至算法就绪耗时。源码与打包CI预算均为2秒，超时返回失败。

## Windows证据与限制

用户12:18这轮运行是源码环境（`frozen=False`），不能将本机macOS的4.03秒直接归因于其Windows。

- 后端首条日志12:18:11.771；全部算法依赖导入完成12:18:12.296，间隔0.525秒，不含进程创建前阶段。
- 开启请求12:18:20.713；成功响应12:18:21.641，间隔0.928秒，此时后台准备已完成。
- 原始日志没有完整进程创建至算法就绪计时。下一次用Windows专用环境运行 `python -m tools.pupil.benchmark_startup <专用python.exe> --source --label repeat --budget 2 --output <报告.json>`；真正首次打包启动须在Windows构建完成后，运行任何打包测试之前，用exe路径替代python、去掉 `--source`、改为 `--label first-after-build`。

现有本机数据不足以承诺所有机器首次启动稳定2秒，也没有把提前打开端口算作算法就绪。物理USB首帧、眼模型稳定与Electron启动不在算法准备基准内。
